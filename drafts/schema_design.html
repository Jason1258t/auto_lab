Normalization (3NF)

  • quotes.claim repeats when a claim has two sources. Accepted for MVP; a claims table is in the backlog.
  • activity_events name copies are historical facts, not current values.
  • llm_calls.model_id records the model actually used.
  • task_reviews.reviewer_id (who reviewed) differs from tasks.reviewer_id (who is assigned).
  • The backend keeps statuses in sync: task done ⇔ an accepted review; call done ⇔ a response row.

Indexes (besides PK and UNIQUE)

  • memberships (user_id), workspaces (owner_id)
  • tasks (workspace_id, created_at DESC)
  • tasks (status) WHERE status IN ('queued', 'running') (partial)
  • tasks (reviewer_id) WHERE status = 'in_review' (partial)
  • task_steps (review_id), llm_calls (task_id, step_index), task_reviews (task_id), quotes (work_source_id)
  • publications (publisher_id, published_at DESC), activity_events (workspace_id, occurred_at DESC)
  • sessions (user_id), user_identities (user_id)
  • Not indexed on purpose: FKs used only when a user is deleted.

Parked for later

  • Reviewer deleted while a task is in_review: nobody can review it (backend logic).
  • What happens to tasks when their model becomes unavailable.
  • failed task state: ignored for now.
  • Secret store: only admins and the system read it; probably not Postgres (.env for MVP).
  • Possible split of models into base model + deployment.
  • After-MVP features (OAuth login, password reset, invites, reports, schedules, …) are in BACKLOG.md.
